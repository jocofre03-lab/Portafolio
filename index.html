Caso de estudio

BookVault: construir sin red

El proyecto que más me exigió, y por qué lo elegí para este portafolio.

La actividad
BookVault es una aplicación web para la gestión de una biblioteca digital, desarrollada como proyecto del Módulo 5 del bootcamp. Permite administrar el catálogo de libros, gestionar usuarios con distintos roles y controlar préstamos y devoluciones.
El desafío
El desafío no fue solo programar la aplicación, sino construirla en Java EE sin un framework que resolviera las cosas por mí, lo que me obligó a enfrentar por mi cuenta problemas de configuración, acceso a datos y lógica de negocio.
Sincronizar el stock con los préstamos. El desafío de diseño más interesante: mantener coherente el stock disponible con los préstamos activos exigía decidir dónde vivía cada responsabilidad y en qué orden ejecutar las operaciones.
Estados inválidos. Al probar la aplicación detecté que un usuario podía solicitar el mismo libro varias veces, generando préstamos duplicados.
Acceso a la base de datos. El usuario root de MariaDB solo permitía conexión con privilegios de sistema, lo que impedía que la aplicación se conectara.
La solución
Para el control de stock, definí que se descuenta al registrar el préstamo y se restaura al procesar la devolución, resolviendo la operación aritmética directamente en SQL con una condición que impide que el valor quede negativo.
Para los préstamos duplicados, implementé una verificación previa que consulta si el usuario ya tiene un préstamo activo de ese título, identificando los activos por tener la fecha de devolución en NULL.
Para el acceso a la base de datos, creé un usuario dedicado con permisos acotados únicamente a la base del proyecto. Además de resolver el problema, es una mejor práctica de seguridad que usar root.
Toda la aplicación quedó organizada con el patrón MVC y una capa DAO independiente para el acceso a datos, usando PreparedStatement en las consultas para prevenir inyección SQL.
Herramientas utilizadas
Java EE, JSP, JSTL, Servlets, JDBC, MariaDB, Maven, Apache Tomcat 9, HTML y CSS. Patrones MVC, DAO y Singleton.
Impacto
Préstamos duplicados eliminados por completo. Antes de implementar la verificación previa, el sistema permitía que un usuario solicitara el mismo libro varias veces. Después del cambio, ese estado inválido quedó bloqueado.
Integridad del stock garantizada. El stock disponible nunca puede quedar negativo ni descuadrado, gracias a la condición aplicada en SQL y al recálculo de copias prestadas al editar el stock total de un libro.
Seis problemas técnicos detectados y resueltos durante el desarrollo, desde el registro del driver JDBC y los permisos de base de datos hasta la codificación UTF-8 y la lógica de sincronización de stock, cada uno con su causa identificada y su solución aplicada.
Aprendizajes
Aprendí a leer un error hasta encontrar su causa real en lugar de probar soluciones al azar, y a tomar decisiones de diseño sobre dónde vive cada responsabilidad dentro de la aplicación. También incorporé la seguridad como parte del desarrollo y no como un agregado al final.
Habilidades aplicadas
Desarrollo web con Java EE, diseño de arquitectura en capas, modelado y consultas SQL, depuración de errores de configuración y entorno, implementación de reglas de negocio y buenas prácticas de seguridad en el acceso a datos.
Por qué elegí este proyecto
Elegí BookVault porque fue el que me presentó los mayores desafíos técnicos. Tuve que enfrentar errores constantes y resolverlos uno a uno, lo que fue un buen aprendizaje de lo que viviré al ingresar al mundo laboral, donde las cosas no siempre funcionan a la primera.
Además, al construirlo sin un framework pude entender cómo funciona todo por detrás, sin dependencias automáticas que resolvieran la configuración por mí.

Es como aprender a manejar: primero mecánico y después automático. Esa base me permite hoy trabajar con Spring Boot entendiendo qué está haciendo por debajo.
